GEOVANI — DEMO FRONTEND PRD
Complete UI-only specification for a working, recordable product demo
1. Product Goal
Build a polished enterprise/government-grade GEOVANI frontend that demonstrates the complete journey: document/data ingestion → Document Intelligence → multimodal RAG → retrieval verification → evidence-linked AI answer → automated report → mining/topic intelligence. No production backend is required; use realistic local mock data and simulated workflows. The product must feel interactive, not like a static PPT.
2. Demo Success Criteria
3–5 minute end-to-end screen recording is possible without manual UI manipulation.
Every important CTA works: navigation, modal/drawer, filter, loading state, preview, generation or toast.
Core architecture is visible through UI, especially Retrieval Verification and source/page traceability.
Mock/demo values are clearly distinguishable from official statistics.
Refresh should preserve important demo state through localStorage.
3. Recommended Stack
React + Vite; React Router; Tailwind CSS; Recharts; Lucide React; Framer Motion.
Local JSON/JS mock data; localStorage for persistence.
Optional realistic document/page preview; no real backend required for the demo.
4. Design System
Desktop-first enterprise intelligence UI; responsive on smaller screens.
Dark navy/charcoal shell, light content surfaces, restrained cyan/blue accents.
Professional industrial/government AI aesthetic; avoid flashy consumer SaaS styling.
Consistent cards, badges, tables, charts, timelines, evidence chips and document previews.
Use subtle animations only to communicate processing/activity.
5. Global Navigation
6. Dashboard
Header: GEOVANI — Mining Intelligence & Reporting.
KPI cards: Documents Indexed, Mines Covered, Evidence-linked Answers, Reports Generated.
Recent ingestion activity with filename, type, status and timestamp.
Visual pipeline: Ingestion → Document Intelligence → Multimodal RAG → Verification → AI Output.
Quick actions: Ask GEOVANI, Upload Document, Generate Report, Explore Intelligence.
Recent reports table and activity feed.
Use mock/demo labels where values are invented.
7. AI Query & Evidence
Large query composer with example mining questions.
Filters: Mine, Subsidiary, Year, Document Type, Topic.
Run Query triggers loading and pipeline animation.
Pipeline stages: Query Understanding → Hybrid Retrieval → Reranking → Retrieval Verification → Answer Generation.
Answer card: concise answer, key findings, evidence count and Verified Evidence badge.
Evidence cards: document, page, section, year, relevance status and View Source.
Source drawer/viewer with page preview and highlighted evidence.
'Why this answer?' expandable trace.
Include a demo where one irrelevant candidate is rejected by verification.
8. Documents
Document library with search, filters, status and document type.
Drag-and-drop upload modal supporting PDF, DOCX, XLSX, CSV, JPG/PNG and map/image examples.
Processing stepper: File Detection → OCR → Layout Analysis → Table/Figure Extraction → Entity Enrichment → Chunking → Embedding → Indexing.
Show progress, current stage and final Indexed Successfully state.
Document detail page with metadata, preview and processing summary.
9. Document Intelligence
Two-column layout: source preview left, extracted intelligence right.
Metadata: Mine, Subsidiary, Location, Year, Report Type, Source.
Tabs: OCR Text, Layout, Tables, Figures/Maps, Entities, Topics/Keywords.
Show page/section mapping so every extracted item can become evidence.
Entities should include realistic mining/geological examples such as mine, seam, equipment, geological feature and location.
10. Reports
Report library with title, type, mine/subsidiary, period, status and actions.
Generate Report wizard: report type, mine/subsidiary, period, sources, output format.
Types: Mine Safety Intelligence, Production Analysis, Geological Summary, Management Brief.
Generation animation: retrieval → verification → analysis → charts → document composition.
Professional in-app A4 report preview with Executive Summary, Key Findings, charts, tables and Sources.
Actions: Download PDF, Download DOCX, Share/Export (demo), Regenerate.
Newly generated reports appear in the library.
11. Mining Intelligence
Topic distribution and ranked keywords.
Keyword cloud or ranked term panel.
Year-wise trend chart.
Mine/subsidiary comparison.
Related documents.
Emerging topics.
Entity explorer: Mine, Seam, Equipment, Geological Feature, Incident, Location.
Clicking an entity/topic filters related documents and insights.
12. Demo Data Model
Use fictional but realistic records: Safety Review FY 2024–25, Mine Production Summary, Geological Exploration Report, Groundwater Assessment Report, Equipment Performance Review and Parliamentary Query Compilation.
Include 2022–23, 2023–24 and 2024–25 periods.
Use several representative mines/subsidiaries.
Every document and chunk needs stable IDs plus page/section references.
Do not present invented values as official CIL/CMPDI data.
13. Mock RAG Engine
Local mock retrieval searches demo chunks using keywords plus metadata filters.
Return top-k candidates.
Mock reranking scores candidates by topic/query overlap.
Verification checks topic overlap, metadata compatibility and required evidence fields.
Candidate status: Verified / Rejected / Needs Review.
Answer is produced from predefined answer templates using verified chunks.
UI must preserve future production flow: Hybrid Retrieval → Reranking → Verification → Private LLM.
14. Critical Demo Script
Open Dashboard and show KPIs + pipeline.
Click Upload Document and select a sample mining report.
Show the processing stepper through OCR, extraction, enrichment, chunking and indexing.
Open Document Intelligence and inspect metadata, entities, table and figure/map.
Open AI Query and ask: 'What are the major safety issues identified in the selected mine reports?'
Show retrieval and reranking stages.
Show one irrelevant chunk rejected by Retrieval Verification.
Show verified evidence from multiple source pages.
Display the source-linked answer and open a source/page viewer.
Click Generate Report and show generation stages.
Open the generated report preview with charts and references.
Open Mining Intelligence and show topics/trends/entities.
Return to Dashboard and show the generated report/activity.
15. Trust & Evidence UX
Every AI answer has visible Source, Page, Section, Year and Document ID.
Show 'Evidence Verified' only after the verification stage.
Expandable retrieval trace shows candidates and outcomes.
Source-not-found state should prevent unsupported answers.
Demo disclaimer: 'Prototype demo — sample data; not an operational decision system.'
Never fabricate model accuracy/confidence percentages.
16. Required UI States
Loading/skeleton states for async-looking actions.
Success, warning and error toasts.
Empty state for filters.
Processing state with progress percentage/current stage.
Verification rejection state.
Source unavailable state.
Confirmation before replacing/deleting demo documents.

20. Non-Goals
No real SAP integration.
No real private vLLM deployment.
No production authentication/authorization.
No production vector database/object storage requirement.
No claim of production-grade security.
No claim that mock answers are produced by a live LLM.
21. Definition of Done
All six pages are fully navigable.
Upload-to-index workflow works locally.
AI query workflow works locally.
Retrieval verification is visibly demonstrated.
Source/page evidence opens.
Report generation creates an in-app preview.
Charts and filters respond.
All major buttons have meaningful demo behavior.
Core state survives refresh via localStorage.
Complete demo can be recorded without editing the UI manually.
22. Final Product Narrative
GEOVANI takes a mining document, understands its structure and content, enriches it with domain metadata, indexes its multimodal information, retrieves relevant evidence for a user question, verifies the retrieved evidence, generates a source-linked answer, and turns the same intelligence into a structured report and mining insights. The frontend must make this journey visually obvious.
